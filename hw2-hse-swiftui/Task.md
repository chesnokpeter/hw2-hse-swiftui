# Домашнее задание: приложение «Список покупок»

## Задача

Создать SwiftUI-приложение, в котором пользователь ведёт список покупок: добавляет позиции, отмечает купленные, ищет и удаляет их, открывает экран подробностей.

Если полностью повторить обязательную часть по этому лонгриду и получить работающий проект, максимальная оценка составляет **6 из 10**. Четыре дополнительных задания оцениваются по **+1 баллу** каждое.

## Что проверяется

- проект собирается и запускается;
- все обязательные сценарии работают;
- в коде корректно используются `View`, `@State`, `@Binding`, `List`, `NavigationStack` и `.sheet`;
- код разбит минимум на модель и три представления;
- к проекту приложен README с перечнем реализованных возможностей.

## Шаг 1. Модель покупки

Создайте Swift-файл `ShoppingItem.swift`.

```swift
import Foundation

struct ShoppingItem: Identifiable, Hashable {
    let id: UUID
    var name: String
    var category: String
    var quantity: Int
    var isPurchased: Bool

    init(
        id: UUID = UUID(),
        name: String,
        category: String,
        quantity: Int = 1,
        isPurchased: Bool = false
    ) {
        self.id = id
        self.name = name
        self.category = category
        self.quantity = quantity
        self.isPurchased = isPurchased
    }
}
```

### Разбор модели

`import Foundation` подключает тип `UUID`. Он нужен, чтобы каждая покупка получила собственный идентификатор.

`struct ShoppingItem` описывает одну покупку. Структура хорошо подходит для небольшой модели значений: когда мы изменяем покупку в массиве, Swift создаёт обновлённое значение этой структуры.

Протокол `Identifiable` требует свойство `id`. `List` и `ForEach` используют его, чтобы отличать одну строку от другой. Название покупки не подходит на роль идентификатора: две покупки могут называться одинаково, а пользователь может переименовать элемент. `UUID` остаётся неизменным и решает обе проблемы.

Протокол `Hashable` позволяет передавать значения, связанные с моделью, через типобезопасную навигацию. В нашем приложении в `NavigationLink` передаётся `UUID`, однако соответствие `Hashable` также делает модель пригодной для других вариантов навигации и коллекций.

Свойство `id` объявлено через `let`, потому что идентификатор не должен меняться в течение жизни элемента. Остальные свойства объявлены через `var`: пользователь сможет изменить название, категорию, количество и статус.

Инициализатор задаёт удобные значения по умолчанию. При создании новой покупки можно не передавать `id`, количество и статус. Swift автоматически создаст идентификатор, установит количество `1` и отметит покупку как ещё не купленную. При этом тестовые данные могут явно передать `isPurchased: true`.

Добавьте тестовые данные:

```swift
extension ShoppingItem {
    static let samples = [
        ShoppingItem(name: "Молоко", category: "Продукты", quantity: 2),
        ShoppingItem(name: "Блокнот", category: "Учёба"),
        ShoppingItem(name: "Батарейки", category: "Дом", isPurchased: true)
    ]
}
```

Расширение `extension` отделяет учебные данные от основного определения модели. Статическое свойство `samples` принадлежит типу `ShoppingItem`, поэтому доступно как `ShoppingItem.samples`. Эти элементы используются только для первого запуска и Preview. После добавления настоящего хранилища тестовые данные можно будет убрать.

На этом этапе проект ещё не показывает список. Запустите сборку через `⌘B`: так вы проверите модель отдельно и сразу увидите синтаксические ошибки.

## Шаг 2. Строка списка

Создайте `ShoppingItemRow.swift`.

```swift
import SwiftUI

struct ShoppingItemRow: View {
    let item: ShoppingItem
    let onToggle: () -> Void

    var body: some View {
        HStack(spacing: 12) {
            Button(action: onToggle) {
                Image(systemName: item.isPurchased
                      ? "checkmark.circle.fill"
                      : "circle")
                    .font(.title2)
                    .foregroundStyle(item.isPurchased ? .green : .secondary)
            }
            .buttonStyle(.plain)

            VStack(alignment: .leading, spacing: 4) {
                Text(item.name)
                    .font(.headline)
                    .strikethrough(item.isPurchased)

                Text("\(item.category) · \(item.quantity) шт.")
                    .font(.caption)
                    .foregroundStyle(.secondary)
            }
        }
        .padding(.vertical, 4)
    }
}
```

### Разбор строки

`ShoppingItemRow` принимает два параметра. `item` содержит данные для отображения. `onToggle` содержит действие без параметров и результата. Строка сообщает о нажатии, но не знает, где хранится массив и как найти нужную покупку. Такое разделение делает представление небольшим и переиспользуемым.

`HStack` располагает кнопку и текстовый блок горизонтально. Параметр `spacing: 12` задаёт расстояние между ними. Внутри кнопки используется SF Symbol. Тернарное выражение выбирает заполненный круг с галочкой для купленного товара и пустой круг для активного.

Модификаторы после `Image` зависят от того же свойства `isPurchased`. Поэтому и символ, и цвет всегда синхронизированы с моделью. Вручную менять цвет после нажатия не нужно.

`.buttonStyle(.plain)` важен внутри `List`: без него область нажатия кнопки может конфликтовать с поведением всей строки или `NavigationLink`.

`VStack` располагает название и подпись вертикально. `alignment: .leading` прижимает обе строки к левому краю. Модификатор `.strikethrough(item.isPurchased)` перечёркивает название только после покупки. В подписи строковая интерполяция `\(…)` вставляет категорию и количество.

Вертикальный `padding` увеличивает высоту строки, не меняя отступы всего списка.

Добавьте Preview, чтобы проверять строку без запуска всего приложения:

```swift
#Preview("Активная покупка") {
    ShoppingItemRow(item: ShoppingItem.samples[0]) { }
        .padding()
}

#Preview("Купленная покупка") {
    ShoppingItemRow(item: ShoppingItem.samples[2]) { }
        .padding()
}
```

Пустое замыкание `{ }` допустимо в Preview: нам нужно проверить внешний вид, а изменение массива здесь не тестируется.

## Шаг 3. Главный экран

Замените код `ContentView.swift`:

```swift
import SwiftUI

struct ContentView: View {
    @State private var items = ShoppingItem.samples
    @State private var searchText = ""
    @State private var showingAddItem = false

    private var visibleItems: [ShoppingItem] {
        guard !searchText.isEmpty else { return items }
        return items.filter {
            $0.name.localizedCaseInsensitiveContains(searchText)
                || $0.category.localizedCaseInsensitiveContains(searchText)
        }
    }

    var body: some View {
        NavigationStack {
            List {
                ForEach(visibleItems) { item in
                    NavigationLink(value: item.id) {
                        ShoppingItemRow(item: item) {
                            toggle(item)
                        }
                    }
                }
                .onDelete(perform: delete)
            }
            .navigationTitle("Покупки")
            .searchable(text: $searchText, prompt: "Название или категория")
            .toolbar {
                Button("Добавить", systemImage: "plus") {
                    showingAddItem = true
                }
            }
            .sheet(isPresented: $showingAddItem) {
                AddShoppingItemView { newItem in
                    items.append(newItem)
                }
            }
            .navigationDestination(for: UUID.self) { id in
                if let index = items.firstIndex(where: { $0.id == id }) {
                    ShoppingItemDetailView(item: $items[index])
                }
            }
        }
    }

    private func toggle(_ item: ShoppingItem) {
        guard let index = items.firstIndex(where: { $0.id == item.id }) else {
            return
        }
        items[index].isPurchased.toggle()
    }

    private func delete(at offsets: IndexSet) {
        let ids = offsets.map { visibleItems[$0].id }
        items.removeAll { ids.contains($0.id) }
    }
}
```

### Разбор состояния главного экрана

`ContentView` владеет тремя изменяемыми значениями:

- `items` — единственный основной массив покупок;
- `searchText` — текст, который пользователь вводит в поиск;
- `showingAddItem` — признак того, нужно ли показывать форму добавления.

Обёртка `@State` нужна для значений, которыми владеет само представление. Когда одно из них меняется, SwiftUI заново вычисляет описание `body`, сравнивает его с предыдущим и обновляет нужные части интерфейса. Не следует выносить эти свойства в обычные локальные переменные внутри `body`: при следующем вычислении они потеряют значения.

`visibleItems` является вычисляемым свойством. Оно не хранит второй массив, а каждый раз получает результат из `items` и `searchText`. При пустой строке поиска возвращается весь массив. При введённом тексте `filter` оставляет элементы, в названии или категории которых есть искомая строка. `localizedCaseInsensitiveContains` выполняет поиск без учёта регистра и лучше подходит для пользовательского текста, чем обычный `contains`.

### Разбор дерева интерфейса

`NavigationStack` создаёт контейнер навигации. Внутри него `List` показывает строки. `ForEach(visibleItems)` получает каждый элемент и строит для него `NavigationLink`.

В `NavigationLink` передаётся `item.id`, а не весь экран. Ниже модификатор `.navigationDestination(for: UUID.self)` описывает, какой экран нужно построить для выбранного идентификатора. Такой подход отделяет действие перехода от создания экрана назначения.

Внутри строки замыкание вызывает `toggle(item)`. Функция ищет элемент в исходном массиве по стабильному `id`, а затем меняет `isPurchased`. После изменения массива SwiftUI обновляет нужную строку.

`.searchable` получает `$searchText`. Знак `$` передаёт двустороннюю привязку: поле поиска читает текущее значение и записывает в него пользовательский ввод.

Кнопка в `.toolbar` не открывает форму напрямую. Она меняет `showingAddItem` на `true`. Модификатор `.sheet` наблюдает за этим состоянием и показывает `AddShoppingItemView`. Когда форма вызывает `onSave`, главный экран добавляет полученный элемент в принадлежащий ему массив.

### Почему удаление написано через идентификаторы

`onDelete` передаёт индексы строк, которые сейчас видит пользователь. При активном поиске это индексы массива `visibleItems`, а не `items`. Например, в исходном массиве искомая покупка может иметь индекс `5`, но в результатах поиска оказаться первой и получить индекс `0`.

Поэтому функция `delete` сначала переводит видимые индексы в идентификаторы, а потом удаляет из исходного массива элементы с этими идентификаторами. Вариант `items.remove(atOffsets: offsets)` работал бы без поиска, но мог бы удалить другую покупку после фильтрации.

После вставки кода проверьте четыре действия отдельно: переключение статуса, ввод поиска, открытие формы и удаление. Если ошибка появилась, вы сразу поймёте, к какой части она относится.

## Шаг 4. Форма добавления

Создайте `AddShoppingItemView.swift`:

```swift
import SwiftUI

struct AddShoppingItemView: View {
    @Environment(\.dismiss) private var dismiss
    @State private var name = ""
    @State private var category = ""
    @State private var quantity = 1

    let onSave: (ShoppingItem) -> Void

    var body: some View {
        NavigationStack {
            Form {
                TextField("Название", text: $name)
                TextField("Категория", text: $category)
                Stepper("Количество: \(quantity)", value: $quantity, in: 1...99)
            }
            .navigationTitle("Новая покупка")
            .navigationBarTitleDisplayMode(.inline)
            .toolbar {
                ToolbarItem(placement: .cancellationAction) {
                    Button("Отмена") { dismiss() }
                }

                ToolbarItem(placement: .confirmationAction) {
                    Button("Сохранить") {
                        let item = ShoppingItem(
                            name: name,
                            category: category,
                            quantity: quantity
                        )
                        onSave(item)
                        dismiss()
                    }
                    .disabled(name.trimmingCharacters(in: .whitespaces).isEmpty)
                }
            }
        }
    }
}
```

### Разбор формы

`@Environment(\.dismiss)` получает системное действие закрытия текущего модального экрана. Форма не должна самостоятельно изменять `showingAddItem` в родительском представлении: окружение позволяет закрыть sheet без знания о том, кто его показал.

Поля `name`, `category` и `quantity` относятся только к незавершённой форме, поэтому форма хранит их через `@State`. Пока пользователь печатает, готового `ShoppingItem` ещё нет.

`Form` группирует стандартные элементы ввода и автоматически применяет системное оформление. `TextField` получает `$name` и `$category`. Знак `$` создаёт `Binding`: поле видит текущее значение и может записывать изменения обратно. `Stepper` работает с `$quantity` и ограничивает число диапазоном `1...99`.

Замыкание `onSave` передаётся из `ContentView`. Форма отвечает за ввод и создание объекта, а владелец массива решает, куда его добавить. Это сохраняет единый источник данных.

При нажатии «Сохранить» код выполняется по порядку:

1. создаётся `ShoppingItem` из текущих значений формы;
2. объект передаётся в `onSave`;
3. `ContentView` добавляет его в `items`;
4. `dismiss()` закрывает форму.

Модификатор `.disabled` обрезает пробелы по краям и проверяет, остались ли символы. Поэтому строку из одних пробелов сохранить нельзя. Категорию пока разрешено оставить пустой: усложнение валидации вынесено в дополнительное задание.

Проверьте форму дважды: сначала попробуйте сохранить пустое название, затем создайте корректную покупку и убедитесь, что она появилась в списке.

## Шаг 5. Экран подробностей

Создайте `ShoppingItemDetailView.swift`:

```swift
import SwiftUI

struct ShoppingItemDetailView: View {
    @Binding var item: ShoppingItem

    var body: some View {
        Form {
            TextField("Название", text: $item.name)
            TextField("Категория", text: $item.category)
            Stepper("Количество: \(item.quantity)", value: $item.quantity, in: 1...99)
            Toggle("Куплено", isOn: $item.isPurchased)
        }
        .navigationTitle("Покупка")
        .navigationBarTitleDisplayMode(.inline)
    }
}
```

### Разбор редактирования через Binding

`ShoppingItemDetailView` не владеет покупкой, поэтому использует `@Binding`, а не `@State`. Binding представляет двустороннюю ссылку на значение, которым владеет другой экран.

В `ContentView` перед переходом находится индекс выбранного элемента:

```swift
if let index = items.firstIndex(where: { $0.id == id }) {
    ShoppingItemDetailView(item: $items[index])
}
```

Выражение `$items[index]` создаёт привязку к конкретному элементу массива. Экран подробностей передаёт дочерние привязки `$item.name`, `$item.category`, `$item.quantity` и `$item.isPurchased` стандартным элементам формы.

Изменения записываются непосредственно в массив `ContentView`, поэтому отдельная кнопка «Сохранить» не требуется. После возврата список уже использует обновлённую модель.

Если заменить `@Binding var item` на обычное `var item`, экран будет редактировать собственную копию структуры. Интерфейс формы может временно показать новое значение, но исходный массив не изменится. Это одна из самых частых ошибок в данном задании.

Откройте любую покупку, измените все четыре поля и вернитесь назад. Убедитесь, что название, категория, количество и статус обновились в списке.

## Шаг 6. Пустой результат поиска

Внутри `List` замените простой `ForEach` условием:

```swift
if visibleItems.isEmpty {
    ContentUnavailableView.search(text: searchText)
} else {
    ForEach(visibleItems) { item in
        NavigationLink(value: item.id) {
            ShoppingItemRow(item: item) {
                toggle(item)
            }
        }
    }
    .onDelete(perform: delete)
}
```

### Разбор пустого состояния

Условие проверяет именно `visibleItems`, потому что пустой экран может возникнуть в двух случаях: исходный список действительно пуст или поиск не нашёл совпадений.

`ContentUnavailableView.search(text:)` создаёт системное сообщение для пустого результата поиска. Ветка `else` сохраняет прежний список и обработчик удаления.

Обратите внимание на место `.onDelete`: модификатор относится к `ForEach`, а не ко всему `List`. Благодаря этому SwiftUI связывает жест удаления с конкретными строками коллекции.

Для более точного интерфейса можно различать два случая: при пустом `items` показывать приглашение добавить первую покупку, а при непустом массиве и пустом `visibleItems` — сообщение о неудачном поиске. В обязательной части достаточно приведённого варианта.
